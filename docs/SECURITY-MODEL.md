# Security model

The protected asset is the first externally effective communication resource: call bridge, SIP leg, WebRTC room, TURN allocation, message thread, notification, callback or equivalent effect.

Threats exercised include handle theft, signature tampering, wrong signer, replay, concurrent double consumption, stale/missing revocation and policy state, nonce change, query/handle expiry, destination and property substitution, business/actor/affiliate pivot, purpose laundering, channel/effect/direction widening, audience substitution, device substitution, quota rollback misuse, uncertain outcomes, capability theft and resource widening.

The implementation assumes that the observed attempt fields are populated by trusted adapters. It demonstrates how the finality engine uses them; it does not authenticate SIP, STIR, mTLS, DPoP, workload or device identity itself.

Security claims apply only to governed paths. If an application, employee, public number, alternate CPaaS credential, notification API or other equivalent route can create the same protected effect without the enforcement point, the stronger communication-finality or absent-path property is not achieved.
